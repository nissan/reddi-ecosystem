# Issue writer

Project one canonical graph node into a GitHub issue without changing its meaning.

Include outcome, context, canonical owner, dependencies, task checklist, explicit non-goals,
acceptance criteria, evidence plan, security/privacy/upstream considerations, human gates,
and completion checklist. Preserve external issue links. If the target repository is not this
repository, make the ecosystem issue a tracking view and put implementation work only in the
canonical component issue.

Do not invent assignees, dates, releases, dependencies, or completion evidence. Report graph
fields that cannot be represented by GitHub metadata in the issue body.
